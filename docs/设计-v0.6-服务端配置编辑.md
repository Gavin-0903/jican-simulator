# 设计：v0.6 首页设置 → 服务端配置编辑

> 目标（用户原话）："在首页加入设置按钮，能编辑服务端的 config 全部设置项"

## 1. 入口

大厅（首页）卡片上的 **⚙ 设置** 按钮（`client/js/ui/LobbySettingsButton.js`，按钮上带一行小字 `config.json`），只在 `PHASE.LOBBY` 阶段显示，进对局后由 `client/js/main.js:210` 的 `applyPhase` 隐藏。点开是独立弹窗（`modals.kind === 'config'`），和 v0.5 的设置弹窗（`SettingsPanel`，`modals.kind === 'settings'`，联机 / 画面 / 操作三标签）是两个不同的宿主，**互不覆盖、也互不替代**——本版只是多了一个入口，v0.5 那个一个字都没改：

| 入口 | 位置 | 什么时候出现 | 打开什么 | 数据源 |
| --- | --- | --- | --- | --- |
| ⚙ 设置 / `config.json`（本版新增） | 大厅（首页）卡片右上角，标题行右端（实测 1280×800 下距卡片右 21px、顶 31px，relX≈80% / relY≈5%；同行顺序 `brand-mark` → 标题块 → `.spacer` → `.lobby-settings-slot`） | 仅 `PHASE.LOBBY`（`main.js:210`），进对局即隐藏 | `ConfigPanel`：三段配置的完整表单（平衡 / 运行 / AI 与 LLM） | `GET /api/config`、`POST /api/config`、`POST /api/config/reset` |
| ⚙ 设置（v0.5） | 对局界面顶部状态栏右侧，与倍速 / 镜头 / 暂停并排（`client/index.html` 的 `#btn-settings`） | 进对局后才能点——大厅阶段整条状态栏被 `client/css/layout.css:72` 隐藏 | `SettingsPanel`：ID 密钥 / 联机服务器 / Token / TailScale + 画面 / 操作 | `GET /api/net/admin`、`GET /api/net/admin/token`、`POST /api/net/token/regenerate`、`POST /api/net/online/mode` |

**读者最容易混的一点**：v0.5 那个 ⚙ 在**首页是点不到的**（状态栏在 `PHASE.LOBBY` 下 `visibility:hidden`），所以「我在首页只看到一个设置按钮」是正常的，不是 v0.6 把 v0.5 挤掉了。反过来，v0.6 这个按钮改不了任何联机状态，要换 TailScale 模式、看 Token，还得进对局点状态栏那个。

**⚠ 一处会被当成 bug 的设计**：大厅里点右上角齿轮**没有任何反应**——那个齿轮是 HUD 状态栏里的 `#btn-settings`，大厅阶段整条状态栏（含 statusbar）被 `client/css/layout.css:72-73` 设成 `visibility:hidden`，元素在 DOM 里但看不见也点不到。所以：**大厅里唯一的设置入口就是本版新增的这个按钮；想打开 v0.5 联机控制台必须先开一局（`PLAYING` / `PAUSED`）**。这不是权限被拦，也没有任何报错——纯 CSS 隐藏，实机表现为「点了像没点」。

面板三段标签，顺序固定为 **平衡 → 运行 → AI 与 LLM**：

| 标签 | section | 内容 |
| --- | --- | --- |
| 平衡 | `balance` | 对局数值：移动、视野、积分、工资、道具等（`config/balance.json`） |
| 运行 | `app` | 服务器与客户端运行参数（`config/default.json`），改完多半要重启 |
| AI 与 LLM | `llm` | 本地模型接入、超时与降级策略（`config/llm.json`） |

每行三态：**生效值**（默认值叠上 override 之后的结果）、**默认值**（来自 `config/*.json` 本体）、**是否被覆盖**。被覆盖的行高亮，右侧有「恢复默认」。顶部搜索框按键名过滤（`move.baseSpeed` 这种点路径），改动只进本地草稿（`this.draft`），底部徽章显示「N 项未保存」。

## 2. 数据流

```
GET  /api/config            → { ok, secrets[], sections, defaults, override, effective, differences }
POST /api/config            → { section, path, value }  或  { section, patch:{点路径:值} }
POST /api/config/reset      → { section? }（省略 = 三段全清）
```

- `sections[段]` = 生效值（已脱敏）+ `meta: { restartKeys, overridePaths }`；`effective` 与 `sections` 同源。
- `defaults[段]` = `config/*.json` 的本体（同样脱敏）；`override[段]` = `override.json` 里真正被改过的键。
- `differences` = `[{ section, path, value, defaultValue }]`，前端拿它做「已覆盖」高亮。
- 「保存修改」对每个改动路径**串行** `POST /api/config { section, path, value }`，不是一次性整包提交——这样单个键被拒（未知键 / 类型不符 / 校验不过）时其它键照常保存，失败的键逐条列在面板里。**不用并发**：串行才能保证 `override.json` 的写入顺序确定、报错可归因。
- `value: null` = **删掉这个键的覆盖**（恢复继承默认值），不是「设成 null」。
- 「重置本段 / 全部重置」走 `POST /api/config/reset`；「恢复默认 / 恢复本组」不走 reset（reset 的粒度是整段，会把同段其它改动一起清掉），而是逐个 `POST { path, value: null }`。

服务端把「校验」与「写入」彻底分开：`validateAll` / `validatePatch` 只算不写，`patchOverride` 只写不算（`server/persistence/ConfigLoader.js:215`），两者各自可单测。

## 3. 生效时机

```
needRestart = section === 'app' && applied 里命中 RESTART_KEYS
```

| 段 | 改了之后 | 依据 |
| --- | --- | --- |
| `balance` | **下一 tick 生效** | 写盘后立刻 `loadConfig` → `controller.setBalance()`；另有 `watchBalance` 每秒轮询兜底（手改文件也生效） |
| `llm` | **立即生效** | `Object.assign(config.llm, next.llm)`（LLM 网关每次请求都读这个对象） |
| `app` 里不在重启表 | **立即进内存**，但只在启动/建局时被读的那些键要等下次用到 | `Object.assign(config.app, next.app)` |
| `app` 里命中重启表 | **必须重启服务** | 见下表 11 项 |

**11 个需要重启的键**（`RESTART_KEYS`，只有 `app` 段有这张表，`llm`/`balance` 段永远是空数组）：

| 键 | 为什么改不了 |
| --- | --- |
| `server.host` | 监听地址在 `listen` 时就定了，改配置不会重新 bind |
| `server.port` | 同上 |
| `server.portFallbackRange` | 同上（端口回退区间只在启动时算一次） |
| `tickRate` | 决定 GameLoop 步长与所有 ms→tick 换算，中途改会让进行中的对局时间轴错乱 |
| `mapId` | 地图在建局时装配进 `GameState`，不重建对局改不了 |
| `roster.classes` | 名单在建局时装配进 `GameState` |
| `roster.studentsPerClass` | 同上 |
| `roster.subjectTeachers` | 同上 |
| `roster.residentTeachers` | 同上 |
| `debug.endpoints` | debug 端点是在 `createHttpHandler` 时按开关挂上去的 |
| `net.maxMessageBytes` | 绑在 `WebSocketServer` 的 `maxPayload` 上，构造后不能改 |

服务端每次写入返回里的 `applied` 就是真正落进 `override.json` 的点路径数组，`needRestart` 只看 `applied` 是否命中上表——**不按 section 一刀切**（改 `app.round.targetScore` 是热生效的，不吓唬用户重启）。前端把命中的键攒成一条黄色提示：「部分配置需要重启游戏才生效：tickRate、server.port」。

## 4. override.json

设置页的写入全部落在 `data/override.json`（**不碰 `config/*.json` 本体**），所以「恢复默认」永远有据可依：

```json
{
  "app": {
    "round": { "targetScore": 3000 },
    "tickRate": 12
  },
  "balance": {
    "flatter": { "min": 5 },
    "ask": { "reward": 88 },
    "items": { "freeze": { "price": 150, "upLevelPrice": "{Lv} * 60" } }
  },
  "llm": {
    "timeoutMs": 1500
  }
}
```

（上面只是示意，真实文件只含被改过的键。三段各自独立，缺段等于「该段没有任何覆盖」。）

存储位置是 `dataDir()`（`server/persistence/paths.js`）：开发机是仓库的 `data/`，安装版是 `%LOCALAPPDATA%\JicanSimulator\`（可用 `JICAN_DATA_DIR` 覆盖）。写入是**原子**的——先写 `override.json.<pid>.<时间戳>.tmp` 再 `rename`（`server/persistence/ConfigLoader.js:160`）。为什么不用直写：进程写到一半被杀会留下半截 JSON，下次启动整份覆盖被当成非法而回退默认值，用户改的设置全丢。

读取规则（`mergeOverride`，`server/persistence/ConfigLoader.js:14`）：

- **只接受已经在 base 里存在的键**，拼错的键记为「未知键」被拒，不会凭空造出配置项；
- 类型必须一致（数字不能塞字符串），否则「类型应为 number」被拒；
- 顶层对象逐层深合并，所以上面 `balance.flatter.min` 只覆盖这一个数，`flatter.max` 保持默认。

`override.json` 解析失败时**不会静默变成空对象**：`readOverride` 返回 `{ __error }`，此时 `patchOverride` 直接抛「override.json 已损坏，拒绝在其上打补丁」，装载期只记一条 warn 并保留旧值。这条是有意的——一次写坏的文件不该让整份配置悄悄回落默认。

## 5. 接口契约

| 接口 | 方法 | 限定 | 说明 |
| --- | --- | --- | --- |
| `/api/config` | GET / HEAD | 回环 | `configAdmin.describe()`，顶层带 `secrets` 点路径清单 |
| `/api/config` | POST | 回环 | body 上限 64 KB；成功 200，校验失败 400，坏 JSON 400 |
| `/api/config/reset` | POST | 回环 | body 上限 4 KB；省略 `section` = 三段全清 |

- 前缀判断在 `server/net/LobbyHttp.js:441`：`path === '/api/config' || path.startsWith('/api/config/')`，所以 POST 走 lobbyRouter（`createHttpHandler` 最优先接管它）。
- 校验失败统一 HTTP **400** 且响应体 `{ ok:false, errors:[{ path, message }] }`，不是 200 带 `ok:false`：前端 `req()` 只看 `r.ok`，400 才能落到错误分支。
- 其它方法 → 405 `{ ok:false, error:'只接受 GET /api/config、POST /api/config、POST /api/config/reset' }`。
- 未注入 `configAdmin` → **501**「本实例未启用配置读写接口」，前端据此把整块 UI 降级成「当前服务端版本不支持配置编辑」，不报错。
- 成功响应：`{ ok, applied:[点路径], needRestart, errors:[], warning? }`；`onApply`（把新值推进运行期）抛错时**仍然返回 ok:true**，另附 `warning: '已写入磁盘，但热生效失败（重启后生效）：…'`——写盘确实成功了，不能谎报失败。
- `reset` 返回 `{ ok, cleared:[点路径], clearedCount, needRestart }`，语义对齐 `apply` 的 `applied`，前端才能说「已清除 3 项覆盖」。

## 6. 安全与限制

- **只对本机开放**。判据是 `isLocalManageRequest`（`server/net/OnlineAdmin.js:38`）：`req.socket.remoteAddress` 必须是回环（`127.0.0.1` / `::1` / `::ffff:127.0.0.1`）**且** Host 头必须解析到本机（`localhost` / `127.0.0.1` / `[::1]`，带端口也算）。两条都满足才算，只满足其一是别的机器或者被 DNS 重绑定劫持的页面。不满足一律 **403**「只允许本机设置页修改联机配置」。
- **没有改 CSP**。页面 CSP 仍是 `connect-src 'self' ws: wss:`（`server/net/HttpServer.js:24`），这些接口全部同源，不需要放宽任何一条。
- **不做 CSRF token，靠来源判定**。理由同上：跨站页面即使能发请求，也过不了「回环来源 + Host 头」这一关；这和既有的 `/api/net/admin`、`POST /api/net/online/mode` 是同一套口径（`/api/app/quit` 更严，额外要 `x-jican-client: launcher` 头）。
- **下发必脱敏**。`GET /api/config` 里 `sections` / `defaults` / `override.app` / `override.llm` 一律过 `maskSecrets`。判据是 `isSecretEntry`：**值必须是字符串且非空**，且要么命中键名（`apikey` / `secret` / `password` / `token`，不区分大小写），要么值本身是 256 位 hex。掩码形态 `前 4 位 + 最多 8 个 * + （共 N 位）`，例如 `sk-a********（共 17 位）`。
- **脱敏路径清单随响应下发**。顶层 `secrets: ['llm.openaiCompat.apiKeyEnv', …]` 是权威来源，前端据此决定哪些输入框只读，不再靠正则猜掩码形状——换打码格式也不会静默失效。
- **掩码串被拒绝写入**。见 §8.1。
- **不碰 `config/*.json` 本体**：设置页永远只写 `override.json`，所以误操作可以用「恢复默认」逐键撤回，最坏情况删掉这个文件即可。
- **写前整包校验**：候选 patch 先合到当前生效值上再跑整包规则（`APP_RULES` / `BALANCE_RULES` / `validateLlm`），而不是单看一个键——单看一个键永远合法（`flatter.min` 自己没毛病，但 `min > max` 就不行）。

## 7. 踩过的坑（都值得记住）

### 7.1 掩码串被当成配置写回，污染了 override.json

第一版 `validatePatch` 只做「键存在 + 类型一致 + 规则通过」，于是出现这样一条路径：用户点开 AI 与 LLM 标签 → 看到 `apiKeyEnv` 那一行显示 `sk-a********（共 17 位）`（脱敏后的展示值）→ 改了别的字段 → 「保存修改」把**所有**草稿里的路径一起提交，而那行的显示值恰好在草稿里 → `override.json` 里出现 `"apiKeyEnv": "sk-a********（共 17 位）"`。

这比报错恶劣得多：它是**写成功了**。之后每次装载都拿着这串假值，表现成「模型一直连不上」，而配置文件看起来完全正常。

修法是双保险：

1. **服务端硬闸**（`server/net/ConfigAdmin.js` 的 `validatePatch`，在 `mergeOverride` **之前**）：遍历 patch（含嵌套对象与数组）找出所有 `isMaskedValue` 命中的值，命中即 400，文案 `llm.openaiCompat.apiKeyEnv（这是脱敏后的显示值，不能作为配置写入；请填入真实值）`。前端拦不住别的调用方（curl、脚本、别的客户端），服务端必须自己拒绝。
2. **前端兜底**：`ConfigPanel.save()` 提交前再筛一遍，把疑似掩码行跳过并在提示里报数「N 项是脱敏后的显示值，不能作为配置写入；请填入真实值」。省一次往返，也避免「假成功」的观感。

`isMaskedValue` 只认「`（共 N 位）`」这个后缀形态，**纯 `*` 串故意不拦**：

```
isMaskedValue('JICA********（共 17 位）')  → true
isMaskedValue('**')                        → false   // llm.maxTokens 的真实值就是 '**'
isMaskedValue('{Lv} * 50')                 → false   // 道具升级价的合法表达式
isMaskedValue('')                          → false
```

宁可漏判纯 `*`（风险低：真写回去也只是个错值，前端展示层还会再打一次码），也不能误伤这些正常配置，让用户连改都改不了。`isMaskedValue` 与 `maskSecret` 是**一对**，改任何一个的格式都必须同步改另一个。

### 7.2 maskSecrets 把对象整体 String() 化，下发了一段非法 JSON

更早一版 `maskSecrets` 对所有「键名像密钥」的值不问类型先 `maskSecret(String(v))`。而 `balance.items.password` **本身就是个对象**（道具叫「强密码」，不是密码字段）：

```json
{ "items": { "password": { "price": 50, "maxLevel": 5, "name": "强密码" } } }
```

于是 `GET /api/config` 把这个对象下发成了字符串 `"[obj********（共 15 位）"`。两个后果：

1. 前端拿到的不再是对象而是字符串，`price` / `maxLevel` 直接变成不可编辑；
2. 这串值**不是合法 JSON 的产物**，前端 `JSON.parse` 之后画出来的表单是个假的，改回去还会覆盖掉整个道具配置。

修法：`maskSecrets` 只对**标量**（`isScalar`）且 `isSecretEntry` 为真的键打码，数组/对象一律继续递归，结构原样保留。`isSecretEntry` 里也补了同样的约束（只认字符串、非空）——数字/布尔打码后会变成写不回去的字符串，对象打码会破坏结构。

回归测试直接钉住了这一点：`tests/unit/config-admin.test.js` 断言 `typeof masked.items.password === 'object'`、`deepEqual` 结构不变、`JSON.parse(JSON.stringify(masked))` 不抛。

### 7.3 reset 只回 `{ ok, needRestart }` 时前端在数「清了几项」

`reset` 早先不返回 `cleared`，前端只能自己扫一遍 `override` 估算「已清除 N 项」，重置后再 `load()` 一次才知道真实结果。现在服务端直接回 `cleared` / `clearedCount`（清掉之前先数一遍），前端退回本地估算只为兼容老服务端。
