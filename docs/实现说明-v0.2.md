# 实现说明 v0.2 — 道具系统与联机自测

日期：2026-10-31。本版本在 v0.1 基础上实现《游戏开发需求文档》2.1 / 2.2 的**道具系统**（服务端全部逻辑），并把联机模块（ID 密钥 / 房间 / 大厅 HTTP）纳入单元测试。下面记录配置字段语义、判定归属、与既有系统的联动方式、协议新增项。所有数值都在 `config/balance.json → items`，评审时可只改配置。

## 一、道具配置字段（`config/balance.json → items`）

| 道具 | 键 | 含义 |
| --- | --- | --- |
| 全部 | `price` | 首次购买价；支持 `{Lv}` 模板，`Lv` = 「买这件之前已经持有几件」，所以第一件按 Lv=1 计价，**重复购买逐件变贵** |
| 全部 | `maxLevel` | 等级上限（定格 10、买通 10、强密码 5、沙漏 15、黑客手册 10） |
| 全部 | `maxUses` | 使用次数上限 |
| 全部 | `upLevelPrice` | 升级价模板，按**当前等级**求值（`Lv1→2` 花 `Lv*50 = 50`，`Lv2→3` 花 100） |
| 全部 | `repeatable` | 是否允许重复购买（`password: false` 表示一件就够） |
| freeze | `perUsePrice` | 补弹价模板：花 `perUsePrice(Lv)*份数`，每份**再给 Lv 次**使用次数；只能给已购满仓的定格手枪补弹（`buyType: "uses"`） |
| freeze / hourglass | `freezeMsPerLevel` | 每级定格时长（1000 ms/级） |
| buyoff | `seeThroughPctPerLevel` | 每级让被买通的老师「视而不见」的百分比（10 → Lv 级命中率 ×(1−0.1·Lv)，Lv≥10 归零） |
| password | `lockMsPerLevel` | 每级解锁耗时（1000 ms/级，Lv5 = 5 秒） |
| hourglass | `maxPerRoundByLevel` | 文档写法 `"ceil(Lv / 2)"`；配置里只是给人看的字符串，**代码现算** `Math.max(1, Math.ceil(lv/2))`（见第四节） |
| hackbook | `failPctBase` / `failPctPerLevel` | 失败率 = `clamp(100 − 10·Lv, 0, 100)%` |
| hackbook | `expelPctBase` / `expelPctPerLevel` | 被开除率 = `clamp(100 − 8·Lv, 0, 100)%` |
| hackbook | `maxPerRound` / `risk` | 每局最多 1 次；`risk: "extreme"` 仅用于客户端文案分级 |

### 价格模板求值规则

`upLevelPrice: "{Lv} * 50"` 这类模板由 `server/systems/ItemSystem.js → evalCost(expr, lv)` 求值：

1. 数字直接返回（四舍五入取整、非负）；
2. 字符串先剥掉花括号（`{Lv}` 是文档占位符），再做隐式乘法归一（`50 Lv` → `50*Lv`）；
3. 只识别 `数字 / Lv / + - * / ( )` 这些 token，递归下降求值，**不使用 `eval`**——配置是可热重载的 JSON，eval 等于把配置变成可执行代码；
4. 结果非有限数或为负时按 0 处理（宁可白送也不算出离谱价格，同时 ConfigLoader 会先把非法表达式拦在加载阶段）。

因此 `ConfigLoader.js` 的 `costExpr` 校验只要求 `price / upLevelPrice / perUsePrice` 是「非负数，或只含 `0-9A-Za-z+Lv+-*/(). {}` 的非空字符串且至少含一个数字或 `Lv`」——注意字符类里**必须放行花括号**，否则契约给的 `"{Lv} * 50"` 会被判非法、整个 balance 加载失败（这正是本轮修复过的一个坑）。

## 二、ItemSystem 在流水线中的位置

`server/core/GameLoop.js` 的 pipeline 现在是：

```text
move → items → interaction → buff → vision → score → win
```

`items` 排在 `move`（被定格的角色的移动在 MoveSystem 里已经被跳过）之后、`interaction` 之前，原因是：

- **指令归属唯一**：`MessageRouter` 把 `item.buy / item.upgrade / item.use` 入队成同名 `inputQueue.type`，`GameLoop.consumeInputs` 把它们原样推进 `pendingActions`（`kind` 就是这三个带点字符串，同时兼容 `ACTION.BUY_ITEM` 等枚举值）。ItemSystem 消费掉自己认识的 kind，**不认识的再塞回去**留给 InteractionSystem，后者永远看不到道具 kind，也就不会在 `default` 分支报「未知动作」。
- **扣钱只发生一次**：购买、升级、使用的全部判定与扣费都在 ItemSystem 内完成，其它系统只**读**道具状态（`frozenUntil`、`items.buyoff.lv`、`items.password.lv`），不写、不扣。
- 购买 / 升级 / 使用时若角色不在 `STATUS.ACTIVE`，直接 `E_ELIMINATED`；被定格则 `E_FROZEN`（自己也被定格时什么都不能做）。

`PendingActions` 在消费前先整体摘下再逐条处理（`c.pendingActions = []`），未识别的动作按原顺序 push 回新数组，保证 InteractionSystem 拿到的顺序与提交顺序一致。

## 三、定格（冻结）语义

定格在状态里是**绝对 tick**：`character.frozenUntil = 冻结到的 tick`，判断统一走 `ctx.frozen(c) => state.tick < c.frozenUntil`（`GameLoop.makeContext`），三个系统各自尊重它：

| 系统 | 行为 |
| --- | --- |
| `MoveSystem` | 被定格时把 `vel` 清零并 `continue`；**不清 `inputDir`**——定格结束后玩家按住的方向键仍然有效（客户端不会重发） |
| `InteractionSystem.update` | 任何 action 在 `handle` 之前 `ctx.fail(c, kind, ERR.FROZEN, '你被定格了')`；但**不强制退出电脑**——强迫退出会把「定格 + 举报」变成一次免费抓人 |
| `InteractionSystem.updateAsking` | 提问进度暂停（`c.asking.ms` 不再累加），定格结束从原进度继续 |
| `ItemSystem.update` | 被定格时道具指令同样 `E_FROZEN` |

`freeze`（定格手枪）对**指定一个角色**生效：`target.frozenUntil = max(frozenUntil, now + freezeMsPerLevel·Lv)`，重复定格取最晚的那个，不叠加也不缩短。`hourglass`（时间沙漏）对**除自己外的全场**（学生 + 老师 + AI）写同一个 `until`。

## 四、每局次数上限（现算，不读配置）

- 沙漏：`Math.max(1, Math.ceil(lv / 2))`（配置里 `maxPerRoundByLevel` 只是文档字符串，不为它写一个迷你表达式解析器）。计数在 `character.itemRoundCount.hourglass`。
- 黑客手册：`Math.max(1, cfg.maxPerRound)`，计数在 `itemRoundCount.hackbook`；**只是打开全员列表不消耗次数**，真正施法（带 `charId + action + amount`）才扣。
- 使用次数统一在 `spend()` 里扣：`uses -= 1`、`itemStats.used += 1`、`itemRoundCount[id] += 1`；次数不足返回 `E_ITEM` 且 `reason: 'uses'`。

## 五、强密码 passwordGate 与一次性放行

判定在 `server/systems/InteractionSystem.js → passwordGate()`，位置在 **`jcCommit` 扣分之前**（`cooldowns.jc` 校验之后、用户名/数量校验之前），并且只读**受害者**的 `items.password.lv`，不看受害者状态——**冷冻中或已淘汰的人持有强密码依然生效**。

流程：

1. 受害者 `lv ≤ 0` → 放行；
2. `attacker.unlock[victimId]` 存在且 `until > now` → 拒绝：`ctx.fail(..., ERR.ITEM, '这台电脑上了强密码，正在破解中', ..., { reason:'locked', victimId, remainMs })` 并 `ctx.dialog{kind:'jc_locked', victimId, remainMs, lockMs}`。重复提交**不重置计时**（否则一直提交就永远解不开）；
3. `attacker.unlockOnce[victimId] === true` → 删掉标记并放行（见下）；
4. 首次触发 → 写 `c.unlock[victimId] = { until: now + toTicks(lockMsPerLevel·Lv), victimId }`，返回同样的 `jc_locked` 对话框与剩余时间。

**unlockOnce 是必须的一次性放行券**：解锁到期后 `ItemSystem.update` 第一步清理过期条目，顺手写 `c.unlockOnce[victimId] = true`。没有它的话，「到期后提交」会被当成「首次触发」重新计时——因为条目已删，判定又回到第 4 步，形成永远解不开的死循环。标记只用一次，避免「破解成功一次之后永久免解锁」。

快照里 `me.unlockRemainMs` 取所有解锁条目的最大剩余毫秒，客户端据此锁定 JC 表单并显示倒计时。

## 六、买通老师：让 VisionSystem 按乘法衰减

生效点在 `server/systems/VisionSystem.js`：对同一次 JC 的每位候选老师先算几何命中率 `p = catchProbability(...)`，再乘买通折扣：

```js
const bribe = actor.items?.buyoff?.lv ?? 0;
if (bribe > 0) {
  p *= Math.max(0, 1 - bribe * (balance.items.buyoff.seeThroughPctPerLevel / 100));
  actor.itemBuyoffSeen = (actor.itemBuyoffSeen ?? 0) + 1;
}
if (ctx.rngOf(t).next() < p) { /* 记入 pendingCatches 并 break */ }
```

「没看见」就是**这次目击作废**：既不阻止 JC（JC 已在本 tick 的 interaction 阶段落账），也不扣攻击者积分、不给老师奖励。Lv ≥ 10 时 `p = 0`，等价于该老师完全看不见。`itemBuyoffSeen` 记录「触发折扣的目击次数」，便于调试与平衡观察。

## 七、黑客手册：双抽（失败 / 开除）与每局上限

`ItemSystem.useHackbook()`：

1. **不传 `charId`/`action`** → 只返回 `ctx.dialog{kind:'hack.targets', list:[{id,name,role,score,me}], failPct, expelPct}`（按老师在前、id 升序排序，含自己），不扣次数；
2. 传 `action ∈ {set, add}` + `charId` + `amount`（`amount ≠ 0`，`set` 表示改成该值、`add` 表示增减；学生改积分、老师改工资），才 `spend()`；
3. 用角色自己的随机子流抽两次：`failed = rng.next()*100 < failPct`、`expelled = rng.next()*100 < expelPct`。**两次都抽**（即使第一次已经失败）——保持随机流消耗次数恒定，否则同一 seed 下的行为会随失败与否漂移，破坏可复现性；
4. 失败：自己 `-100` 分（同时 `knownDelta -= 100`，自己的「已知变化」要诚实地反映这笔损失），`itemStats.hackFail += 1`，目标不变，emit `ITEM_FAILED` + `HACK_RESULT{ok:false}`，对话框 `hack_result{ok:false, penalty:100}`；
5. 成功：`target.score = (set ? amount : target.score + amount)`，学生同步 `knownDelta`，`itemStats.hackSuccess += 1`，emit `HACK_RESULT{ok:true, amount: delta}`，对话框 `hack_result{ok:true, delta, score}`；
6. 无论成功失败，`expelled` 为真都调用 `expel()`：`status = STATUS.ELIMINATED`、清 `frozenUntil / asking / opLock / operatingPcId`、释放电脑、`state.stats.eliminations += 1`、`dialog{kind:'close', reason:'eliminated'}`、emit `EVENT.ELIMINATED`，人类玩家还要 `state.result ??= { reason: END_REASON.PLAYER_ELIMINATED, winnerId: null }`（与 `ScoreSystem` 的淘汰分支完全一致）。

另有一条保护：`buyoff` 与 `hackbook` 这两件**依赖「老师看得见」**的道具，在有老师正处于定格状态时使用会被拒绝（`E_ITEM`, `reason:'teacher_frozen'`）——否则「先用砂漏冻结所有老师再买通 / 黑进系统」能零成本白嫖。

## 八、新增消息 / 对话框 / 事件 / 错误码

### C → S 消息（详见 [协议速查](protocol/websocket-protocol.md)）

| type | payload |
| --- | --- |
| `item.buy` | `{itemId, amount?, buyType?}` |
| `item.upgrade` | `{itemId}` |
| `item.use` | `{itemId, targetId?, charId?, amount?, action?}` |
| `item.list` | `{}` |

`item.*` 直接入 `inputQueue`，在流水线中由 ItemSystem 消费；**不能**复用 `input.action`——那条消息的 payload 白名单只有 `kind / pcId / targetId`，塞不下 `charId / amount / action`。

### S → C 对话框（`dialog.kind`）

| kind | 字段 | 时机 |
| --- | --- | --- |
| `item_bought` | `itemId, lv, uses, score` | 购买成功 |
| `item_upgraded` | `itemId, lv, score` | 升级成功 |
| `item_used` | 定格：`itemId, targetId, ms, uses`；买通：`seeThroughPct, lv`；强密码：`lockMs, lv`；沙漏：`ms, affected, limit, used` | 使用成功 |
| `hack.targets` | `list, failPct, expelPct` | 黑客手册打开全员列表 |
| `hack_result` | 成功 `{ok:true, targetId, delta, score, expelled}`；失败 `{ok:false, targetId, penalty, expelled}` | 黑客手册结算 |
| `jc_locked` | `victimId, remainMs, lockMs` | JC 撞上强密码 |

失败统一走 `error` 通道（`code = E_ITEM / E_FROZEN / E_ELIMINATED`，`kind` 回指动作），并在 `me.lastResult` 留痕。

### 事件（`events[].type`）

| type | 字段 | 可见性 |
| --- | --- | --- |
| `item_bought` | `actorId, itemId, amount(花费), buyType?` | 全局；补弹为 actor |
| `item_upgraded` | `actorId, itemId, amount(花费)` | actor |
| `item_used` | `actorId, itemId`（买通 / 强密码） | actor |
| `frozen` | `actorId, targetId?, itemId, amount(ms), pos` | 全局 |
| `item_failed` | `actorId, targetId, itemId, amount(-100)` | actor |
| `hack_result` | `actorId, targetId, ok, amount(delta)` | actor |
| `eliminated` | `actorId, amount(score), pos` | 全局 |

### 错误码

| code | 含义 |
| --- | --- |
| `E_ITEM` | 道具相关失败（金币不足 / 已拥有 / 满级 / 次数用完 / 本局次数上限 / 参数非法 / 强密码锁定中），细节看 `lastResult.reason` |
| `E_FROZEN` | 被定格期间不能移动或行动 |

`reason` 取值：`gold / owned / maxLevel / uses / round_limit / buyType / target / action / amount / locked / teacher_frozen`。

## 九、快照新增字段

- `chars[].fz`：剩余定格毫秒（`max(0, round((frozenUntil - tick) * stepMs / 100) * 100)`）。定格是全员可见的公开效果，不做可见性裁剪。
- `me.items`：`{freeze:{lv,uses}, buyoff:{…}, password:{…}, hourglass:{…}, hackbook:{…}}` 深拷贝。
- `me.itemPrices`：`{ [id]: { price, upLevel, perUse } }`——当前等级下的买入价、下一级升级价（已满级为 `null`）、补弹单价（仅 freeze 有）。让客户端不必重复实现定价公式。
- `me.itemRoundCount`：本局各道具已用次数（沙漏 / 黑客手册据此显示剩余次数）。
- `me.itemStats`：`{bought, upgraded, used, goldSpent, hackSuccess, hackFail, frozenTimes}`，结算面板用。
- `me.frozenMs`：自己剩余定格毫秒（等同 `chars[self].fz`，省得客户端去 `chars` 里翻）。
- `me.unlockRemainMs`：自己在别人电脑上触发的强密码解锁剩余毫秒（取最大），客户端据此锁定 JC 表单。

## 十、ConfigLoader 新增的 `items.*` 校验

`server/persistence/ConfigLoader.js → BALANCE_RULES` 追加（价格用 `pos` 而非 `int`，因为要容纳 `"{Lv} * 50"` 这类字符串模板）：

```text
items.freeze.price / maxUses / maxLevel / freezeMsPerLevel
items.buyoff.price / maxLevel / seeThroughPctPerLevel(0..100)
items.password.price / maxLevel / lockMsPerLevel
items.hourglass.price / maxLevel / freezeMsPerLevel
items.hackbook.price / maxLevel / failPctBase(0..100) / failPctPerLevel / expelPctBase(0..100) / expelPctPerLevel / maxPerRound
```

外加 `validateConfig(label='balance')` 里的交叉校验：`freeze` 配置缺失即报错；每件道具的 `price / upLevelPrice / perUsePrice` 只要出现就必须通过 `costExpr`（非负数字，或只含数字 / `Lv` / 运算符 / 花括号的字符串）——否则升级价会被 `evalCost` 算成 0，等于白送。

## 十一、与 v0.1 的差异 / 未做

- 道具只影响服务端权威状态；客户端只做展示（商店、道具栏、定格遮罩、黑客面板），由客户端线实现：`client/js/ui/ItemShop.js`、`ItemBar.js`、`HackPanel.js`、`items.js`。
- 道具不会让角色说台词：`FlavorService` 的 `LINES` 表没有道具相关 kind，未知名会静默回退成 `idle` 台词，反而更吵，因此道具路径不调 `ctx.say`。

### SEA 打包三条硬约束（踩坑记录）

1. SEA 的 `main` 按 **CJS** 加载 —— 入口必须是 `.cjs`（`.mjs` 报 `Cannot use import statement outside a module`）。
2. SEA 运行期**没有文件系统模块加载能力**：`require('./sea-assets.cjs')` 报 `ERR_UNKNOWN_BUILTIN_MODULE`，资源读取逻辑必须**内联进入口文件**。
3. `sea.getAsset(key)` **不传 encoding 时返回 ArrayBuffer**（第二个参数会被忽略），必须 `Buffer.from(sea.getAsset(key)).toString('utf8')`，否则拿到 `undefined`。
4. `assets` 只接受单个文件，因此把全部 139 个资源序列化成一个 `bundle.b64` 塞进去；`ws` 依赖必须一起打（`packaging/build.mjs` 的 `INCLUDE_PKGS`），否则运行期报 `Cannot find package 'ws'`。
