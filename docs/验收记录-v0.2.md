### 新增联机用例（14 项）

ID 密钥：`computeIdKey` 输出 256 位纯小写 hex 且不同输入互异；`isValidIdKey` 拒绝 `'abc'`、大写 hex、255 长与 `null`。
房间注册表：`create` 返回 `{id, token, invCode}` 且房间号 6 位数字；同一 ID 密钥重复建房 → status 500 且违规计数累计，连续 3 次后 `isBanned` 为真；每人最多一间；`join` 需房间号 + Token + 邀请码三者全对，token 错 / 邀请码错 / 房间不存在均 500；加入成功会结清违规计数。
联机 URL：`parseRoomUrl` 完整解析 origin/token/idKey/type/roomId/invCode/username；缺 token、缺 id、type 非法、join 缺 roomid、非 URL 全部 `ok:false`；`buildRoomUrl` 与 `parseRoomUrl` 往返一致。
大厅 HTTP（真实 `node:http` 起在 0 端口用真 `fetch`）：`/api/net/info` 返回 200、`access-control-allow-origin: *`、256 位 idKey；`/api/net/join` 带非法 id 密钥返回 500 并提示「ID 密钥格式非法」；create 建房返回 `wsPath` 且同房可用 token + 邀请码加入，token 错与房间不存在均 500；未知路径不接管（404）、OPTIONS 预检 204。

另外 `npm run lint`：105 个 JS/JSON 文件语法与格式检查通过。

## 回归说明：本轮修过的四个问题

这四个问题都在交付前被发现并修掉，留档是为了以后改道具系统时别踩回去。

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 发 `item.buy` 后指令被静默丢弃（放开后又会报「未知动作」`E_BADMSG`） | `GameLoop.consumeInputs` 只认 `move` / `action` / `jc.commit` 三类，`item.*` 根本没进 `pendingActions`；若直接放开，InteractionSystem 的 `default` 分支又会把它当未知动作 | `server/core/GameLoop.js:167` 显式把 `item.buy` / `item.upgrade` / `item.use` 入队、`kind` 直接用消息名；这批 kind 只有 ItemSystem 消费（判定只在一处，不重复扣钱） |
| 2 | 首次购买的道具 `uses` 是 0，买了等于没有 | 首购只写了 `lv=1`，没写满仓次数；后续只有在 `buyType='uses'` 时才累加 | 首购时把 `slot.uses` 初始化成 `maxUses`，`buyType='uses'` 只负责补弹 |
| 3 | 强密码永远解不开：到期后提交又被判成「首次触发」重新计时 | `passwordGate` 只看 `c.unlock[victimId]` 是否还在来判断「首次触发」，而解锁到期后 ItemSystem 会删掉这条记录，于是下一次提交从零重新计时 | 过期清理时写一次性放行标记 `c.unlockOnce[victimId]=true`（`server/systems/ItemSystem.js:95`），`passwordGate` 先消费该标记直接放行（`server/systems/InteractionSystem.js:195-198`），标记只放行一次 |
| 4 | 道具用例靠分数差命中目击，被测的 `targetScore` 一改就飘 | 断言间接依赖 JC 数额；几何命中率用默认插值，随站位变化 | 测试显式设 `catchProbabilityLerp=[1,1]` 让几何命中率恒为 1，再在 VisionSystem 实例上覆写 `rngOf` 固定抽签，断言只看被买通后的实际结论 |
